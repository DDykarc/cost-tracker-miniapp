# 数据隔离方案

## 结论

用云数据库的**预设权限「仅创建者可读写」**就能实现多用户数据隔离，
不需要登录系统，也不需要在查询里手写 `_openid`。

## 原理

云开发会给每条记录自动打上 `_openid`（创建者的微信唯一标识，前端无法伪造）。
当集合权限设为「仅创建者可读写」时：

- **查询**：云开发自动在查询条件里补上 `_openid == 当前用户`
- **写入**：自动把当前用户的 `_openid` 写进记录，且不允许前端指定
- **改 / 删**：别人的记录会被拒绝（`doc.update` 表现为返回 `updated: 0`，不报错）

所以前端代码不需要任何额外处理。

## 需要做的（只有一步）

云开发控制台 → 数据库 → 选中集合 → 权限设置：

| 集合 | 权限 |
|------|------|
| `items` | 仅创建者可读写 |
| `health_records` | 仅创建者可读写 |
| `version_info` | 所有用户可读 |

## 验证方式

1. 用自己的微信录入几条数据
2. 用朋友的微信打开小程序，应该看到空列表
3. 朋友录入数据后，你这边也看不到他的

## 常见误区

### ❌ 在云函数里用 setPermission 设置权限

`wx-server-sdk` 的 `Database` 类只有四个方法：
`collection` / `createCollection` / `runTransaction` / `startTransaction`，
**没有 setPermission**。

写 `db.collection(name).setPermission(...)` 会抛 `TypeError`；如果外面套了
空的 `catch (e) {}`，就会变成「看起来执行成功，实际什么都没做」——
权限一直停留在控制台里的设置值。

权限只能在云开发控制台配置，或调用开放平台的 HTTP 接口
（`modifydatabaseacl`，需要 access_token）。

### ❌ 在小程序端手写 `_openid: 当前用户`

小程序端拿不到自己的 openid（这是安全设计）。
预设权限下系统会自动补条件，所以也不需要写。

### ⚠️ 预设权限与自定义安全规则，二选一，不要混用

| | 预设「仅创建者可读写」 | 自定义安全规则 |
|---|---|---|
| 查询是否自动加 `_openid` | 是 | 否，必须手写 |
| `doc.update` 改他人数据 | 不报错，返回 `updated: 0` | 直接拒绝 |
| 代码改动 | 无 | 所有查询 / 更新 / 删除都要带 `_openid: '{openid}'` |

如果用自定义安全规则，查询条件必须「覆盖」规则（子集原则）。
例如规则是 `doc._openid == auth.openid`：

```js
// 会被拒绝：查询条件没有覆盖规则里的 _openid 限制
db.collection('items').doc(id).get()

// 正确写法
db.collection('items').where({ _id: id, _openid: '{openid}' }).get()
```

**本项目采用预设权限方案**，因此 `utils/` 里的查询代码不写 `_openid`。
如果将来要切换到自定义安全规则，需要同步修改 `utils/itemRepo.js`
和 `utils/healthRepo.js` 里的全部查询。

## 不需要做的事

- 不需要登录页面、用户注册、微信授权弹窗
- 不需要存储用户 token
- 不需要在查询里手动过滤 `_openid`
