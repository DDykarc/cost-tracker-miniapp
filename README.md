# 回本清单

记录每件商品的日均使用成本，还有血糖、尿酸、体重等健康数据追踪。

## 功能

### 回本清单
- 记录商品价格、购买日期、分类、图片
- 自动计算已用天数和日均成本，按成本高低着色
- 按分类筛选商品
- 全部物品对比图（横向条形图，按日均成本排名）
- 消费月报 / 年报（分类占比、月度趋势、花费 Top 5）

### 健康记录
- 血糖记录（支持空腹/餐后等多种测量时机）
- 尿酸记录（支持服药标记，按性别判定参考范围）
- 体重记录（自动计算 BMI、目标体重差、N 天对比）
- 数据统计：最高 / 最低 / 平均值
- 趋势图表（支持拖动、双指缩放、点击查看数值）
- 数据导出 CSV

## 技术栈

- 微信小程序原生开发
- 微信云开发（CloudBase）：云数据库 + 云存储 + 云函数

### 分层约定

- **页面**只调用 `*Repo` 暴露的方法，不直接碰 `wx.cloud`
- **Repo** 负责数据读写：成功 resolve 数据，失败 reject 一个带可读文案的 Error
- **calc / chart / format** 是纯函数，不依赖 wx API，可以在 Node 里直接跑单测
- 所有常量集中在 `config.js`，改分类或参考范围只需要改一处

## 使用

1. 用微信开发者工具导入项目，填入自己的 AppID
2. 开通云开发环境，把 `utils/config.js` 里的 `CLOUD_ENV` 改成你的环境 ID
3. 创建数据库集合并**设置权限**（见下一节）
4. 编译运行

### 数据库权限（必须手动配置）

云开发控制台 → 数据库 → 选中集合 → 权限设置：

| 集合 | 权限 | 说明 |
|------|------|------|
| `items` | 仅创建者可读写 | 每个人只能看到自己录入的物品 |
| `health_records` | 仅创建者可读写 | 健康数据同理 |
| `version_info` | 所有用户可读 | 版本信息是公开的 |

「仅创建者可读写」是预设权限，云开发会**自动**在查询条件里补上
`_openid == 当前用户`，所以前端代码不需要手写 `_openid`。

> 若改用「自定义安全规则」，规则就变成显式的了：查询条件必须自己带上
> `_openid: '{openid}'`，否则会报 `-502003` 权限错误。两种模式不要混用，
> 详见 [docs/数据隔离方案.md](docs/数据隔离方案.md)。

## 开发

### 跑单测

计算、格式化、图表坐标这些纯逻辑都有单测覆盖，改完可以直接验证：

```bash
node test/calc.test.js       # 日均成本、BMI、健康状态、统计
node test/format.test.js     # 日期时间格式化与解析
node test/chart.test.js      # Y 轴刻度、条形行高、文字截断、圆角路径
node test/wxml-lint.js       # WXML 标签配对 + 组件引用自检
```

### 几个容易踩的坑

- **单次查询上限是 20 条**：小程序端 `limit` 的默认值和最大上限都是 20
  （云函数端才是 1000）。写 `limit(100)` 不会报错，但会被服务端静默截断成
  20 条，表现就像「数据丢了」。需要全量数据时用 `utils/cloud.js` 的 `fetchAll`。
- **`where` 是覆盖不是合并**：链式 `.where(a).where(b)` 只会保留 `b`，
  多个条件必须写在同一个对象里。
- **`doc.update()` 可能静默失败**：权限为「仅创建者可读写」时，改别人的记录
  不会报错，只返回 `updated: 0`。所以更新后要检查影响条数。
- **图片要存 `cloud://` 的 fileID**：本地临时路径（`wxfile://`）在小程序重启后失效。
